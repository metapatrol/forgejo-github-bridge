# forgejo-github-bridge-grafana-dashboard

Grafana dashboard for forgejo-github-bridge (deployed as a ConfigMap for the Grafana sidecar)

## Chart Info

| Field | Value |
|---|---|
| Version | `0.1.0` |
| App Version | `0.1.0` |
| Type | `application` |

## Usage

This chart deploys the Grafana dashboard for forgejo-github-bridge as a
ConfigMap. It is designed for the [Grafana sidecar](https://github.com/grafana/helm-charts/tree/main/charts/grafana#sidecar-for-dashboards),
which discovers dashboards by a configurable label.

It is a separate chart from `forgejo-github-bridge` on purpose: a dashboard
belongs to whichever namespace the Grafana sidecar watches, which is usually
not the one the bridge runs in.

Set `serviceMonitor.enabled=true` on the `forgejo-github-bridge` chart so
Prometheus scrapes the bridge, or point a scrape config at its `http` port.

```bash
helm upgrade --install forgejo-github-bridge-grafana-dashboard \
  oci://zot.metapatrol.local/charts/platform/forgejo-github-bridge-grafana-dashboard \
  --kube-context k3s-dev -n monitoring
```

## What it shows

| Row | Answers |
|---|---|
| Overview | which version runs, whether exactly one instance is active, what is queued and failing, how long the oldest item waits, how stale the least recent poll is, and GitHub's rate-limit budget |
| Polling | time since the last successful poll per repository and side, poll errors, poll duration |
| Queue | queued against failing, the oldest wait, and what marks items dirty: polls or the full resync |
| Reconciling | reconciles by outcome and by repository |
| What the bridge did | every write on GitHub and in Forgejo by kind and action, and counts for the selected range: issues imported and published, pull requests imported, commits followed, pull requests touching CI, comments crossed |
| GitHub API | the rate-limit budget over time |

The queries are filtered by `$job` and `$namespace`, discovered from
`forgejo_github_bridge_build_info`, and by `$repository`.

The dashboard is generated by `dashboards/generate.py` (`make dashboard`);
`tests/chart` fails when a panel queries a metric the bridge does not
publish, or a published metric has no panel.

## Values

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| grafana.dashboard.enabled | bool | `true` | Enable the Grafana dashboard ConfigMap |
| grafana.dashboard.folder | string | `"Platform"` | Grafana folder name. Leave empty to use the default folder (no annotation set) |
| grafana.dashboard.folderAnnotation | string | `"grafana_folder"` | Annotation key used to specify the Grafana folder |
| grafana.dashboard.label | string | `"grafana_dashboard"` | Label key used by the Grafana sidecar to discover dashboards |
| grafana.dashboard.labelValue | string | `"1"` | Label value used by the Grafana sidecar |
